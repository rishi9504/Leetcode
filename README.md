This repository combines historical accepted submissions with a pattern-oriented revision layer. Synced problem folders remain canonical; generated indexes provide the interview-practice views.

## Repository Contract

Each physical problem folder has three distinct responsibilities:

- `solution.py` or `solution.sql` is the historical accepted submission.
- `README.md` may be generated by the LeetCode sync action.
- `REVISION.md` contains custom interview-preparation metadata and concise revision notes.

Problems are never physically regrouped by pattern. A problem's slug is its canonical identity; the numeric folder prefix is a sync ID and may differ from the frontend LeetCode ID.

## Revision Workflow

Edit a canonical problem's `REVISION.md`, then refresh and validate the generated navigation:

```powershell
python scripts/build_revision_indexes.py
python scripts/validate_revision_metadata.py
python scripts/build_revision_indexes.py --check
```

All migrated problems begin with `confidence: yellow`. Confidence changes only through manual revision. The [must-redo queue](revision/queues/must-redo.md) is generated from `redo: true`; the weak queue is generated from `confidence: red`.

## Sync Safety

The existing workflow at `.github/workflows/sync_leetcode.yml` remains unchanged. Keep custom knowledge in `REVISION.md`; do not hand-edit sync-managed problem statements or accepted solutions as part of repository organization work.

Phase 1 covers the 334 physical synced problem folders and the 26 former root-level legacy solutions. The 209 accepted solutions stored only inside `dashboard/problems.json` are intentionally deferred to Phase 2.
